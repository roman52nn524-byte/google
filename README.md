# Салюты · CRM 2026

## Установка в Google Таблицы (один раз)

1. Загрузите **fireworks-crm.xlsx** на Google Диск. Откройте и выберите **Файл → Сохранить как Google Таблицы**. В режиме редактирования XLSX окно Apps Script не работает.
2. В новой Google Таблице откройте **Расширения → Apps Script**.
3. Вставьте содержимое `Code.gs` вместо начального кода. Создайте HTML-файл с именем **Sale** и вставьте `Sale.html`.
4. В настройках проекта Apps Script установите часовой пояс **Europe/Moscow**; такой же часовой пояс установите в настройках таблицы. Сохраните проект.
5. Перезагрузите таблицу. Появится меню **🎆 Салюты**. Выберите **Новая продажа**. При первом запуске предоставьте скрипту доступ к этой таблице. Публикация как веб-приложения не нужна.
6. Для отдельной кнопки: **Вставка → Рисунок**, создайте кнопку «Новая продажа», затем в ее меню **Назначить скрипт → newSale** (без скобок). Для печати аналогично `routeSheet`.

## Перед началом работы

- Проверьте цены: перенесены значения колонки N исходного склада, чей заголовок — 02.04.2023. Актуальность этих цен неизвестна.
- Сверьте три отрицательных остатка (помечены в колонке «Проверка» листа «Склад»). Они сохранены без исправления и не доступны для продажи.
- Сделайте одну пробную продажу в **копии** таблицы: две позиции, частичная оплата, доставка. Сверьте остатки, сумму и долг; повторное нажатие сохранения не должно создавать второй заказ. Тестовую копию затем можно удалить.

## Что внутри

- **Обзор** — новые продажи, валовая прибыль, долг, стоимость свободного склада и помесячная сводка 2026 года.
- **Продажи** — одна строка на заказ, клиент, получатель, доставка, платежи и состав.
- **Позиции** — детализация для автоматического списания склада. Закупочная цена фиксируется на дату продажи.
- **Склад** — 328 позиций. «Старт свободно» перенесен из исходного «Наличие», поэтому старый резерв уже исключен. Доступно = старт + новый приход − новые продажи.
- **Приход** — новые поступления: дата, ID товара из склада, документ, положительное целое количество. Поля прихода вводятся вручную. Сами по себе они не пересчитывают среднюю закупочную цену: обновляйте ее в каталоге.
- История заказов и исходный XLSX исключены из GitHub-комплекта, чтобы не публиковать данные клиентов. Сохраните их у себя отдельно.

## Правила учета

Оплата товаров и доставки учитывается отдельно. «Оплачено товаров» — вся полученная сумма за товары, включая аванс. Галочка полной оплаты заменяет ее стоимостью товаров. К получению = товары − оплата товаров + неоплаченная доставка. Валовая прибыль = товары − закупочная стоимость; налоги, расходы курьера, реклама и прочие расходы в нее не входят.

Все новые продажи сразу списывают товар. **Статус информационный**: смена статуса на «Отмена» ничего не возвращает. Автоматические резервы, возвраты и отмены в эту версию не входят. Для исправления ошибочной продажи сохраните резервную копию и удалите соответствующий заказ из «Продажи» и все его строки из «Позиции» вместе. Частичные изменения нарушат учет.

Маршрутный лист показывает все новые заказы с адресом доставки, сортируя по дате и времени. Выполнение доставок автоматически не отслеживается; перед печатью сверяйте список. В маршрутном листе есть данные получателя, товары и сумма к получению, закупочные цены не выводятся.

Не меняйте имена рабочих листов, заголовки и порядок столбцов. Не редактируйте ID и ключ запроса. Формулы рассчитаны на строки 2–10000; скрипт останавливает запись по достижении предела. Архивные продажи не попадают в новую выручку — это предотвращает повторный учет при переходе.

## Что проверено

Структура XLSX, перенос 328 товаров и снимок свободных остатков; 12 автоматических проверок серверных расчетов и ограничений. Включены проверка суммарного количества повторяющихся товаров, отрицательных остатков, частичной/полной оплаты, доставки, дат и формульного ввода.

Google Apps Script в вашем аккаунте не запускался. Авторизация, реальное сохранение заказа, пересчет формул после импорта и печать требуют проверки после установки. Блокировка документа защищает от параллельных продаж через форму; прямые ручные изменения склада не защищены этой блокировкой. Ключ запроса предотвращает повторную запись одного отправленного заказа. Запись двух листов выполняется с очисткой при обычной ошибке; абсолютной транзакционности при принудительном прерывании Apps Script нет.
